# NCSR API: Frontend Developer Guide

Backend: Laravel 12, JWT auth (`php-open-source-saver/jwt-auth`, guard `api`). All endpoints are JSON and live under `/api`.

> **Live reference.** Once Scramble is installed (see `SETUP.md`), the interactive, always-current docs are at `/docs/api` and the machine-readable OpenAPI spec at `/docs/api.json`. Use that as the source of truth for request and response fields. This guide covers the things the generated docs can't: auth flows, conventions, and how to use the spec in the Next.js app.

## 1. Quick start

- **Base URL:** `<your-api-host>/api` (ask the backend owner for staging and production hosts).
- **Headers on every request:** `Accept: application/json` and `Content-Type: application/json`.
- **Authenticated requests:** `Authorization: Bearer <access_token>`.

## 2. Authentication

There are two separate login systems.

### 2a. Staff users (JWT)

`POST /api/auth/login`

```json
{ "email": "user@example.com", "password": "secret123" }
```

- `email` accepts an email address **or a phone number**. `password` must be at least 6 characters.
- Success (200) returns `status`, `message`, `access_token`, `token_type` (`bearer`), `expires_in` (seconds) and a `user` object (`id`, `facilityId`, `firstName`, `lastName`, `email`, `phoneNumber`, `role`, `hasNationalAccess`, `dataScopeType`, `facility`, `status`).
- The server also sets two **httpOnly cookies**: `access_token` (2 days) and `refresh_token` (14 days).
- Failures use `{ status: false, code, message }`:

| HTTP | `code` | Meaning |
|---|---|---|
| 404 | `USER_NOT_FOUND` | No account for that email/phone |
| 403 | `ACCOUNT_INACTIVE` | Account disabled |
| 401 | `INVALID_CREDENTIALS` | Wrong password |
| 422 | n/a | Validation errors (standard Laravel shape) |

**Other auth endpoints** (all need the bearer token): `GET /api/auth/me`, `POST /api/auth/refresh`, `POST /api/auth/logout`.
`refresh` reads the `refresh_token` **cookie**, so call it with `credentials: "include"`. Its error codes are `REFRESH_TOKEN_MISSING` and `REFRESH_TOKEN_INVALID` (401).

**Use `user.hasNationalAccess` and `user.dataScopeType` from the login/me response** to decide what the UI shows. Do not derive access from the role name.

### 2b. Clients (patient portal): phone + OTP

1. `POST /api/client-portal/send-otp`
2. `POST /api/client-portal/verify-otp` returns the client session token (see the live docs for the exact response field).
3. Send that token as `Authorization: Bearer <token>` on `/api/client-portal/*` endpoints.

Client tokens only work on `/client-portal/*` routes. Staff tokens do not work there.

## 3. Conventions

- **Validation errors:** HTTP 422, `{ "message": "...", "errors": { "field": ["..."] } }`.
- **Auth errors:** 401 when the token is missing or expired. 403 for inactive accounts or insufficient access.
- **Facility scoping:** most staff endpoints automatically limit results to the facilities the logged-in user may see. National roles see everything. You never pass a facility filter to get this behaviour.
- **IDs:** clients are addressed by their string `clientId` (for example `FMCJ-ABI-ABS-000001`), not a numeric id, in `/clients/{client}` routes.
- **Pagination:** `GET /api/clients` returns Laravel's standard paginator (`data`, `current_page`, `last_page`, `per_page`, `total`, `links`), 20 per page, `?page=2`, `?search=` (name, phone or clientId). `GET /api/visits` uses `?page`, `?limit`, `?search`, `?visitType`, `?filter` (`this_month` or `pending_followups`).
- **Field names are camelCase** (for example `dateOfBirth`, `stateOfResidence`).

| Field | Type | Rules |

## 5. Using the spec in Next.js

```bash
npx openapi-typescript <api-host>/docs/api.json -o src/types/api.d.ts
```

Re-run this whenever the backend changes and TypeScript will flag any breaking change. If the docs page is not reachable from your machine, ask for the exported `openapi.json` (the backend runs `php artisan scramble:export`).
